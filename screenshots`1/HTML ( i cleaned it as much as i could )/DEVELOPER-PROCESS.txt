PRODUCT RULES YOU MUST NOT "DECIDE LATER"
-----------------------------------------
These are locked. Full detail is in the spec you get after you agree.

  Sessions
    Each tab is its own session. Two tabs never share.
    Same-tab refresh within about 20-30 minutes = same session.

  Presence and Send
    Viewing the tab = Connected. Not viewing = Idle. Those are the only two.
    Send works only if they are Connected. It does not queue.
    You cannot move someone who is Idle.
    Clicking a page only chooses it. Nothing moves until Send.
    When Admin selects another session, the right-hand menu resets.
    Visitors do not walk the site. No autoflow.
    Continue / submit goes to that family's loading page, then wait for Send.

  Admission and exits
    Session only by coming through the starting page.
    domain.com and domain.com/ go to that starting page. 
    No session + deep URL = offline URL.
    Enable panel on = site on. Enable panel off = offline URL for
    everyone already on the site and all new people. Admin still works.
    Offline URL = database default, not a settings picker.
    Settings exit URL starts as a copy of offline URL. Admin can change it.
    X uses the settings exit URL.

  Live boxes vs saved history
    Live [ dddd ] on Admin is the websocket view. That is not the
    database history table.
    Seed-phrase boxes: database keeps every keystroke in order and
    locks after submit or redirect.
    Other boxes: save on submit; later typing updates the same box.

  Admin
    One Admin. One live key at a time. Never two valid keys.
    Sign-in may use a key in the URL, then a clean Admin URL. for example domain.com/admin/login=key-DKDKD-DKDKD-DKDKD > domain.com/admin after logging in
    Refresh and logout = type the key again.
    New key is created OUTSIDE Admin. Not a button inside the panel.
    Default: Telegram bot Client controls (message / command, bot
    sends the new key). Or another generate-outside-Admin path.
    Client and Developer will agree which before that work is built.
    That new key immediately kills the old one.
    Anyone still on the old key is signed out.
    The bot and generate path must stay locked down if the VPS
    is exposed. Do not log the raw key in chat, git, or the Admin UI.
    Three card types per page, as in the spec.
    Some cards (especially Coinbase) let Admin type text that
    changes on the visitor page after Send (example last-2).
    Preview is never a real session. Visitor only changes after Send.

  Notifications
    A slight sound only. No popup.
    New session joins, and again when they hit that family's loading page.

  Look
    Visitor pages = supplied HTML / layout for Coinbase and every
    listed wallet. Rebuild, do not redesign.
    Admin = the screenshots / examples already sent.
